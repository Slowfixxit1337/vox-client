# Vox Client

Стендовый клиент проверяет TLS, согласует версию по WSS и входит в комнату.
Настройка `lab,webrtc` подключает клиентский ICE/DTLS к SFU через билет
из управляющего API. Экран `desktop` показывает состояние соединения.
Подключение транспорта само по себе не подтверждает голос или E2EE.

```powershell
cargo test --locked --features lab
cargo build --locked --features lab,webrtc --bins
.\target\debug\vox-lab.exe init --out .\lab-private --sfu-url wss://vox-lab.test:8443/v1/sfu
.\target\debug\vox-client.exe --dev --server vox-lab.test:8443 --lab .\lab-private\client-a.toml --media-route sfu
```

На втором клиенте используйте `client-b.toml`. Передайте на стенд
`admission.toml` и создайте отдельный `lab-sfu.key` на сервере для API и SFU
командой `openssl rand -hex 32 > lab-sfu.key`. Профиль клиента хранится у
его владельца. Для лабораторного CA можно указать `test_ca = "test-ca.pem"`
в начале каждого профиля с путём относительно TOML. Без этого поля клиент берёт
корни из системного хранилища. Проверка имени или IP в SAN обязательна
в обоих режимах. Билет отправляется исключительно по WSS того же origin.

## Лабораторный голос

Добавьте `--voice` к команде `vox-lab init` и выберите новый каталог для
каждого прогона. Ключи AES-GCM для двух направлений хранятся в профилях
клиентов. Передайте каждому клиенту его профиль по доверенному каналу.
API и SFU получают только файл допуска и собственный контрольный ключ.
Формат медиашифрования этого стенда использует LiveKit FrameCryptor.

Запустите оба клиента с их профилями и добавьте `--audio tone` к команде
выше. Каждый вычисляет частоту принятого PCM и выводит `E2EE tone decoded`
при обнаружении тона второго клиента. Для отрицательной проверки создайте
новые профили и замените только `receive_key` клиента A на случайные 32 байта
в шестнадцатеричном виде. A должен вывести `DecryptionFailed`, а Б должен
по-прежнему обнаружить тон A. Для ручной проверки с устройствами Windows
используйте `--audio mic`. Этот режим открывает микрофон после ICE/DTLS.

## Лабораторная передача VP8

Добавьте `--video` к `vox-lab init`, а при запуске обоих клиентов
добавьте `--video test`. У видео свои одноразовые ключи в секции
`[video]` клиентских профилей. Клиенты передают синтетические кадры
через трек `ShareVideo` и выводят `E2EE VP8 test video decoded`,
когда декодер распознаёт изображение второго клиента. Проверку можно
совместить с `--audio tone`. Режим не открывает камеру и захват экрана.

## Демонстрация окна и монитора через SFU

Для демонстрации соберите клиент с `lab,desktop,webrtc`, добавьте `--video`
к `vox-lab init` и запустите оба клиента с `--video share` на
совместимом SFU. Подключение открывает окно Vox с контролами источника и
областью «Демонстрация собеседника». Кадры выбранного источника поступают
в предпросмотр и в зашифрованный трек `ShareVideo`. Лабораторный VP8
ограничен 1280 × 720 с сохранением пропорций.

Захват начинается после выбора окна или монитора. Кнопка «Остановить» и
закрытие выбранного окна прекращают публикацию. У зрителя превью
очищается спустя две секунды без кадров.
Режимы с рамкой и без неё используют те же разрешения Windows, что и
локальный предпросмотр.

### Звук приложения

Свежая пара профилей `vox-lab init --video` включает отдельные ключи
`[share_audio]`. После начала показа нажмите «Приложение для звука» и
выберите игру. Vox захватывает звук этого процесса и его потомков через
WASAPI и отправляет отдельную дорожку Opus с E2EE. Микрофон управляется
независимо. У зрителя кнопка «Заглушить звук демки» выключает только
воспроизведение этой дорожки.

Если Windows не поддерживает изолированный захват, выбранный процесс
закрывается или доступ к нему потерян, видео продолжается со статусом
«Без звука» и причиной. Выход Vox и общий звук устройства в дорожку
игры не подаются. Системный захват и USB/HDMI-вход в этот режим не входят.

Сквозная проверка создаёт собственное тестовое окно. В интерактивном сеансе
Windows укажите адрес стенда и пути к двум свежим клиентским профилям в
`VOX_TEST_SERVER`, `VOX_TEST_PROFILE_A` и `VOX_TEST_PROFILE_B` и выполните:

```powershell
cargo test --locked --features lab,desktop,webrtc --bin vox-client shares_owned_wgc_window_over_sfu_and_stops -- --ignored
```

## Локальный предпросмотр захвата Windows

```powershell
cargo build --locked --features lab,desktop --bin vox-client
.\target\debug\vox-client.exe --capture-preview
```

«Окно с рамкой Windows» запускает WGC с системным выбором окна. «Монитор без
рамки» открывает список дисплеев в Vox и захватывает выбранный дисплей через
DXGI Desktop Duplication. В пробе DXGI поддерживается обычная горизонтальная
ориентация и не добавляется отдельный аппаратный слой курсора.

«Окно без рамки» запрашивает разрешение Windows на захват без обводки,
затем открывает системный выбор источника. Для режима нужен пакет с
`graphicsCaptureWithoutBorder` и Windows с поддержкой `IsBorderRequired`
(build 20348 или новее). При отказе или отсутствии поддержки Vox показывает
ошибку. Кнопка «Окно с рамкой Windows» остаётся доступной.

Цветовая рамка относится к локальному индикатору Windows. Предпросмотр
показывает размер кадра, а «Остановить» и закрытие источника завершают
захват. Режим работает без API, SFU и микрофона. Кадры проходят через D3D11
readback и загружаются в GPUI.

Соберите стендовый MSIX с помощью `packaging/capture-lab/pack.ps1`.
Передайте `-Exe` с путём к сборке `lab,desktop`, `-MakeAppx` с путём к
`makeappx.exe` из Windows SDK, `-Output` с именем нового `.msix` и
`-Publisher` с Subject сертификата подписи. Сценарий выпускает неподписанный
пакет. Для установки подпишите его доверенным сертификатом с указанным
Subject. Пункт «Vox Capture Lab» в меню «Пуск» открывает предпросмотр.

Проверка захвата, изменения размера и закрытия синтетического окна требует
интерактивного сеанса Windows с поддержкой WGC и D3D11:

```powershell
cargo test --locked --features lab,desktop --bin vox-client reads_frames_from_a_test_window_after_resize -- --ignored
```

Проба нативных зависимостей на Windows x64:

```powershell
cargo check --locked --features lab,desktop,webrtc
cargo test --locked --features webrtc --test native_webrtc
```
